12 · Technical · Data

Content model proposed shapes

// shared type Localized = { fr: string; ar: string } // content/products.ts type Product = { id: string name: Localized range: Localized // flour type description: Localized image?: string // empty → logo placeholder packaging?: string[] // bag sizes }
// content/testimonials.ts type Testimonial = { id: string author: string role?: Localized text: Localized } // empty array → band, page, menu entry hidden // content/faq.ts type Faq = { question: Localized answer: Localized }
// content/site.ts export const site = { name: 'SARL Minoterie Ouled Lamri', brand: 'LA COLOMBE', phone: '+213661370011', whatsapp: 'https://wa.me/213661370011', email: 'contact.minoterie@ouled-lamri.com', hours: [ ... ], coords: { lat, lng }, // pending social: { facebook, instagram } }

Principles

  • Text content in content/*.ts, UI strings in messages/*.json
  • Components never hold copy, they receive typed props
  • Replacing a placeholder never changes a component
  • Empty collections hide their section automatically
  • No image set: a still logo placeholder fills the slot
  • Types are the contract between front end and content

What the back end has to deliver

1Contact actionServer Action submitContact or POST /api/contact
2ValidationServer-side schema (e.g. zod), trim and sanitize input
3Anti-spamHoneypot field, rate limit per IP proposed

SEO and delivery checklist

  • Title and description in FR and AR for "minoterie Bordj Bou Arréridj"
  • sitemap.xml and robots.txt
  • Alternate language links between FR and AR pages
  • Local business structured data from site.ts
  • Images through next/image, explicit sizes, WebP/AVIF
  • Fonts through next/font, subset per locale
  • Mobile-first, no horizontal scroll from 320 px
  • Lighthouse mobile: performance ≥ 90, accessibility ≥ 95
